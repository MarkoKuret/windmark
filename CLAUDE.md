# Windmark — working rules

Read `README.md` for the layout and `docs/ROADMAP.md` for what is being built and why.

## Commits
- One short line with a type tag, then (only if needed) a blank line and short bullets:
  ```
  [feature] Boat generator: parametric hull from class file

  - sections from beam/depth/rocker curves
  - deck line and transom
  ```
- Tags: `[feature]`, `[fix]`, `[docs]`, `[refactor]`, `[test]`, `[chore]`, `[perf]`, `[data]`.
- No co-author lines, no author or tool mentions.

## Working
- Never launch a windowed game or GUI without asking the owner; headless runs are fine.
- Design specs in `docs/specs/` are the source of truth for behaviour; code follows them, and a behaviour change
  updates the spec first.
- Boat data is generated by our tools (`tools/vpp`, `tools/boatgen`) from boat-class files; don't hand-edit
  generated tables.
- Third-party code and assets: permissive licences only (MIT, BSD, Apache-2.0, CC0, CC-BY with attribution);
  record each one in `docs/THIRD_PARTY.md`.
- No `timeout` binary on the development Mac.
